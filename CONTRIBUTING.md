# Contributing

1. Create a short lived branch using `feature/`, `fix/`, `refactor/`, `chore/`, `docs/` or `security/`.
2. Use Conventional Commits, for example `feat(web): add course editor` or `docs: clarify release process`.
3. Keep changes scoped; do not commit secrets, local environment files, generated dependencies or unrelated repository content.
4. Run available formatting, lint, typecheck, tests and production build. Explain any unavailable check in the PR.
5. Open a PR to `main`, resolve conversations and wait for required CI. Squash merge is recommended. Do not force push or bypass checks.

See [GitHub Actions](docs/github-actions.md) and [release process](docs/release-process.md).
